## Refuted or corrected claims
- **CN-1 summary ("no amounts or customers shown"):** refuted. The invoice `<select>` renders `"{number} - {customer} ({total})"` (`pages/CreditNotes.tsx:853`). The native control and the dialog divergence are real.
- **UC39 example ("Wayne would see $ here and € on their customer page"):** refuted. Wayne has no billing profile and no invoices, so `CustomerDetail.tsx:263-265` also falls back to the workspace default, and both pages show $ (consistent with CU-17). The two resolvers do differ, which is why UC39 is PARTLY. Underneath, credits have no currency in the domain (`internal/credit/*`, ADR-100).
- **POL-1 ("the form contradicts the saved data"):** overstated. The server only requires at least `max-1` entries (`internal/dunning/service.go:1554-1559`), so 4 entries for 4 retries is valid. The real problem is a silently unused 4th step and a hint that reads like an exact count.
- **UC33 ("quietly creates a webhook pointing at example.com"):** partly right. The endpoint is created inactive (`internal/recipe/service.go:543-547`) and the card lists it, so nothing is delivered. It is still dead data, and it explains the unexplained "paused" endpoint in SH-27.
- **INV-18 cause:** the cited `InvoiceAttention.tsx:88-90` only renders the value. The cause is server-side: `attentionSince` returns `IssuedAt` for simulated invoices (`internal/domain/invoice_attention.go:942-947`).
- **INV-8 details:** the missing border on VLX-000002 is the TableBody `last-child` rule (`components/ui/table.tsx:36`), not something unexplained. VLX-000007 shows no amber edge in W/m-invoices.png, so the "000007/4/3" list is only partly right. The root cause (colour taken from `payment_status`) is confirmed.
- **SH-10 severity "broken":** downgraded to confusing. All four missing pages are reachable from the sidebar.
- **SH-3 "put Live/Paused on a connection pill":** a "Live · 20 events" pill already exists (H/webhook-event-expanded.png). Only "Paused" is missing.
- **SH-18:** the pill means "no unsaved changes" (`!hasChanges`), not "this tenant saved". It is a misleading word, not false state, so I rated it polish.
- **Checked and not refuted:** SH-7 (active customers), INV-6 (counts) and UC20 (plan count) all hold up against code and the live API.
